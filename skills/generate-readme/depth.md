# Уровень, иллюстрации и бюджет текста

Канон для окна вопросов, длины README и рисунка функционала. Сюда смотрят `SKILL.md`, `PROMPT.md` и `codex-prompt.md`. Тип проекта и уместность секции `## Что внутри` остаются в [project-classify.md](project-classify.md). Обложка остаётся в [logo-cover.md](logo-cover.md).

Полный режим не удлиняет прозу. Он добавляет рисунок и более ясное форматирование. Один пункт по-прежнему одно предложение.

## Когда спрашивать

Сначала тихий Scan и Classify. Запиши черновик, включая `walkthrough` (ниже). Файлы не пиши.

Затем одно окно, до Cover и Write. В Grok вызови `ask_user_question` одним вызовом на четыре вопроса. В другой среде используй её инструмент вопросов. Инструмента нет: задай те же четыре вопроса одним сообщением и остановись до ответа.

Вопрос пропускай, только если это же сообщение пользователя уже содержит ответ (таблица фраз ниже). Все четыре ответа есть: окно не открывай.

Окно закрыто без ответа: не жди. Бери рекомендованный вариант каждого вопроса и назови этот выбор в отчёте.

## Четыре вопроса

Рекомендованный вариант помечай `(Recommended)`.

1. **Уровень.** «Какой уровень README сделать?»
   - **Карточка.** Intro, запуск, команды, короткое дерево, лицензия. Без `## Что внутри`, стека и тестов.
   - **Обычный.** Полный каркас README и короткий текст.
   - **Полный.** Тот же текст плюс максимум иллюстраций функционала.
   - Рекомендация: **Обычный**. Фраза полного режима в сообщении переносит рекомендацию на **Полный**, фраза карточки - на **Карточку**.

2. **Степень иллюстраций.** «Как показать функционал?»
   - **Без рисунка.** Обложка на месте, схемы и анимации нет.
   - **Схема.** Статичный SVG карты возможностей.
   - **Анимация.** Та же схема плюс HTML-сцена обхода.
   - Рекомендация по уровню, если пользователь ещё не выбрал степень:

     | Уровень | Рекомендация |
     |---------|--------------|
     | карточка | Без рисунка |
     | обычный | Схема, если фактов секции больше шести. Иначе без рисунка |
     | полный | Анимация, если `walkthrough=yes`. Иначе схема |

3. **Обложка.** «Что сделать с обложкой?»
   - **Оставить**
   - **Перерисовать**
   - Рекомендация: **Оставить**, если есть `docs/cover.svg` или `docs/preview.png`. Файла нет: всё равно создать по [logo-cover.md](logo-cover.md). `docs/preview.png` остаётся обложкой. «Перерисовать» обновляет SVG, только когда preview нет.

4. **Объём.** «Что обновить?»
   - **Только README**
   - **README и правила агентов**
   - Рекомендация: **README и правила агентов**.
   - «Только README» не меняет `AGENTS.md`, `CLAUDE.md` и `.mdc`. `LICENSE` создай, только если файла ещё нет.

| Фразы | Ответ |

| «карточка», «коротко», «glance» | уровень: карточка |
| «обычный», «standard» | уровень: обычный |

| «без рисунка», «без иллюстраций», «только текст» | степень: без рисунка |
| «схема», «диаграмма» | степень: схема |

| «перерисуй обложку» | обложка: перерисовать |

## Обход функционала

`walkthrough=yes`, если человек проходит шаги в продукте: открыть, выбрать, запустить, увидеть результат. Сюда входят web-app, окно desktop, mobile, бот с пользовательскими командами, учебный плеер.

`walkthrough=no` у library, cli без интерактива, infra, monorepo-tool и каталога скиллов. Нет трёх реальных шагов с именами из кода: обхода нет.

Полный режим рекомендует анимацию только при `walkthrough=yes`. Пользователь всё равно может выбрать анимацию сам или отказаться от неё. Выбрал анимацию при `walkthrough=no`: не выдумывай шаги. Поставь схему и напиши в отчёте, почему сцены нет.

## Уровни и секция «Что внутри»

| Уровень | Секция | Рисунок по рекомендации |
|---------|--------|-------------------------|
| карточка | нет | нет |
| обычный | до 6 пунктов или до 6 строк таблицы | схема, только если фактов больше шести |
| полный | тот же потолок | анимация при обходе, иначе схема |

Явный выбор степени важнее колонки «по рекомендации».

Карточка со схемой или анимацией: после intro стоит рисунок, заголовка `## Что внутри` и списка нет.

Обычный и полный: рисунок первый внутри `## Что внутри`, затем короткий список или таблица. Текст не пересказывает кадры и подписи рисунка.

Факты сверх потолка идут на схему, в анимацию или в одну строку `Подробности:` со ссылками на docs, которые уже есть. Новый markdown ради свалки не создавай.

## Бюджет текста

На всех уровнях.

| Блок | Форма |
|------|-------|
| intro | 2 предложения: что это и одно ключевое решение |
| Что внутри | таблица уровней выше |
| Запуск | одно предложение предпосылок, затем команды. Особые условия: второй абзац до 2 предложений или таблица до 4 строк |
| Команды | таблица. Под ней не больше 2 предложений |
| Стек | только бейджи |
| Тесты | одно предложение. Команду повторяй, только если её нет в таблице команд |
| Архитектура | абзац до 2 предложений, дерево, 3-5 инвариантов по одной строке. На карточке абзаца нет, инвариантов до 3 |
| Лицензия | как [license.md](license.md) |

Пункт списка: `**ключ**: одно предложение`. В нём одно ограничение и не больше трёх имён через запятую. Вторая мысль становится новым пунктом, строкой таблицы или ссылкой.

Абзац не длиннее двух предложений и не повторяет соседний список.

`###` внутри секции ставится, когда в ней две группы. Подзаголовок не возвращает длинный пункт.

Пары «возможность и один предел» пиши таблицей из двух колонок. Те же пары списком не дублируй.

Пустая строка отделяет вводное предложение от списка, таблицы или рисунка.

`text-naturalizer` и `sepia` идут после черновика и не имеют права раздуть пункт до двух предложений. Раздуло: верни одно предложение. Набор секций задаёт уровень, не эти скиллы.

## Схема и анимация

Каталог `docs/readme/`. Старые `inside.svg` и `inside.html` не удаляй. При степени «без рисунка» убери на них ссылки из README и назови оставшиеся файлы в отчёте.

### Схема

`docs/readme/inside.svg`. Это карта возможностей, не вторая обложка: без крупного бренд-вордмарка. Фон, сетка и цвета из [logo-cover.md](logo-cover.md). Префикс id `{p}-in-`, чтобы не столкнуться с обложкой. Без `<script>`, внешних href и `<use>`.

3-6 групп. В группе название и одна строка. Подписи на языке README. Сюда переезжают факты, которые не вошли в шесть пунктов секции. `viewBox="0 0 1600 900"`.

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1600 900" role="img" aria-label="Что внутри {name}">
  <title>Что внутри {name}</title>
  <!-- фон и сетка по logo-cover.md, id: {p}-in-bg, {p}-in-glow -->
  <!-- 3-6 групп: rect, короткое название, одна строка факта -->
</svg>
```

В README:

```markdown
<img src="docs/readme/inside.svg" width="720" alt="Что внутри {name}" />
```

### Анимация

Схема обязательна и при анимации: на GitHub остаётся картинка. Сцена открывается по ссылке.

Прочитай `SKILL.md` скилла `html-motion` и собери одну Browser-сцену:

- файл `docs/readme/inside.html`
- задача сцены: обход функционала, не дерево репозитория
- 3-7 beats, каждый beat - шаг человека, имена экранов и команд взяты из кода
- DotCore, если у проекта нет своих токенов
- до 20 секунд, loop можно
- без сети и CDN
- смысл читается при `prefers-reduced-motion`
- это не `launch-video`

Под рисунком, только если файл создан:

```markdown
[Открыть анимацию](docs/readme/inside.html)
```

Нет скилла `html-motion`: поставь его той же командой, что `sepia` и `text-naturalizer` в `SKILL.md`. Не встал: оставь схему и напиши об этом в отчёте. Проверка сцены идёт по QA `html-motion`. Браузера нет: не называй сцену проверенной.

## Поля отчёта

Добавь в отчёт из [audit.md](audit.md):

```
Depth:    card | standard | full
Visual:   none | schema | motion
Walkthrough: yes | no
```

`card` - карточка, `standard` - обычный, `full` - полный. `none` - без рисунка, `schema` - схема, `motion` - анимация.
