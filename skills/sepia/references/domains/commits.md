# Domain - commit messages

Покрывает сообщения `git commit` и короткие описания PR. Гонять с [professional-pass.md](../professional-pass.md) (short-answer weighting). Не писать коммит, пока пользователь явно не попросил.

Канон площадки DotCore: Conventional Commits, одна строка, без соавторов и хвостов ИИ.

## Human baseline

Зачем, не что. Одна строка до 72 символов, scope по модулю если он очевиден. Тело - только если без него не понять риск или миграцию. Автор - пользователь, не модель.

## AI tells в этом домене

| Маркер | Фикс |
|---|---|
| `Co-Authored-By:`, `Generated with`, `Made with Cursor` | Удалить. Коммит от имени пользователя |
| Тема перечисляет файлы («update README and AGENTS and skill») | Сказать намерение: `docs: add sepia skill to catalog` |
| Вода: «improve», «enhance», «update files», «various fixes» | Конкретный объект и причина |
| Тело повторяет subject абзацем | Тело только для why / breaking / миграции |
| Восклицания, emoji, «exciting» | Сухая строка |
| Несколько несвязанных тем в одном сообщении | Это не слог - это плохой коммит; разнести или сказать, что так нельзя |

## Правила

1. Формат: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` + опциональный `(scope)` + описание на английском до 72 символов, если так принято в репо. Русский subject - только если история репо уже на русском.
2. Subject - императив или нейтральный факт (`add`, `fix`, `port`), не «added»-отчёт.
3. Не выдумывать scope. Нет модуля - без скобок.
4. Не коммитить. Этот домен пишет *текст* сообщения, когда коммит уже запрошен.
