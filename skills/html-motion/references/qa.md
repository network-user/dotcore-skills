# QA для HTML-анимации

Используй этот чеклист после первой рабочей версии и после изменения timeline.
Скриншот одного кадра не доказывает плавность: проверяй переходы и состояние
страницы во времени.

## Browser pass

Проверь в доступном браузере:

1. Открытие напрямую или через простой локальный server. Нет ошибок в console.
2. Wide viewport и narrow viewport. Нет случайного `document.body.scrollWidth`
   шире `document.documentElement.clientWidth`.
3. Первый beat, середина, handoff и финал. Главный объект не скачет, не
   перекрывает текст и не выходит за stage.
4. Повторный запуск или loop boundary. Сцена не накапливает DOM-узлы, listeners,
   timers или `requestAnimationFrame` loops.
5. `prefers-reduced-motion: reduce`. Смысл, финальные состояния и controls
   остаются доступны; необязательное движение выключено или заменено быстрым
   fade.
6. Keyboard path для controls: Tab, Enter/Space, Escape, если эти состояния есть.

Если проект предоставляет browser/e2e-инструмент, используй его. Если нет,
выполни доступные статические проверки и явно отметь, что визуальный pass не
запускался.

## Performance pass

Ищи сначала реальные причины, а не убирай всю анимацию:

- `transform` и `opacity` предпочтительнее layout-свойств;
- один RAF loop на сцену, без параллельных loop-ов от компонентов;
- read/write DOM-фазу не перемешивать в каждом кадре;
- `delta` ограничивать после возвращения вкладки из background;
- большие blur, shadow, canvas и WebGL слои считать дорогими до измерения;
- `will-change` использовать только во время ближайшего движения;
- offscreen или завершённые loops останавливать;
- очистить timers, observers, listeners и RAF при unmount/перезапуске.

Не обещай 60 FPS без измерения. Для Canvas ориентир - не превышать бюджет около
16.7 ms на кадр при 60 fps, но проверяй целевое устройство и разрешение.

## Video-ready contract

Если HTML предназначен для покадровой записи, он должен открыть небольшой
управляемый интерфейс:

```js
window.__duration = 8.4;
window.__ready = Promise.resolve();
window.__renderAt = (timeMs) => {};
window.__seek = (seconds) => {
  // pause every running animation first, then call __renderAt(seconds * 1000)
};
```

Правила:

- `__seek(t)` идемпотентен: один и тот же `t` даёт один и тот же кадр;
- время не зависит от того, успел ли браузер отрисовать предыдущий кадр;
- CSS/WAAPI animation не должна свободно играть во время screenshot;
- Canvas рендерится от `t`, а не от количества вызовов `requestAnimationFrame`;
- seed, viewport, fonts и assets фиксированы;
- exporter ждёт `__ready`, затем после каждого seek ждёт минимум два RAF;
- дождись `document.fonts.ready` и загрузки изображений до первого seek;
- не используй screenshot option, которая «отключает анимации» и фактически
  переводит их в end state: timeline должна управляться собственным seek.

До экспорта проверь минимум `t=0`, начало каждого beat, середину transition,
финал и один повторный вызов того же времени. Smoke-test должен снять хотя бы
три кадра, убедиться, что они не пустые, а повторный кадр того же `t` стабилен
по геометрии и цветовым токенам. Для MP4 проверь metadata: codec, width/height,
fps и duration; для web-раздачи обычно нужны `yuv420p` и `+faststart`, а silent
audio track добавляй только если это требование целевой платформы.

## Проверка содержания

- текст читаем без движения и контрастен на выбранной поверхности;
- акцент не является единственным носителем смысла;
- декоративные слои не перехватывают pointer events;
- нет placeholder copy, мёртвых кнопок или неиспользуемых controls;
- финальный кадр намеренно стоит или намеренно возвращается в loop.
